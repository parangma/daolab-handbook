느슨한 커뮤니티의 프로젝트는 쉽게 시작되고 쉽게 흐지부지됩니다. 원인은 대개 하나입니다. **참여의 자유가 실행 약속까지 대신할 수 있다**는 가정.

## 흔들리는 다섯 지점

| 지점 | 흔들리는 모습 |
|---|---|
| 관심 | 관심 표현을 시간 투입 약속으로 본다 |
| 과제 | 목표가 크고 개인이 맡을 일이 모호하다 |
| 책임 | 공동책임 속에 최종 책임자가 사라진다 |
| 가시성 | 지연과 방향 오류를 마감 직전에 발견한다 |
| 기여 | 기여 권한과 최종 승인 권한이 섞인다 |

## 프로젝트를 열 때

- [ ] "관심 있어요"와 "이번 주 두 시간 낼게요"를 따로 묻는다
- [ ] 팀원, 리더, 검토자를 정한다
- [ ] 맡은 영역보다 내놓을 결과물을 약속한다
- [ ] 결과를 닫을 사람 한 명을 정한다
- [ ] 진행률 대신 초안이나 데모로 짧게 확인한다
- [ ] 끝나는 날을 정한다. 영구 프로젝트는 만들지 않는다
- [ ] 늦어지면 범위를 줄이거나 넘기는 방법을 미리 정한다

참여는 자발적으로 열어 두되 약속은 명시적으로 받습니다. 커뮤니티는 가능성을 만들고, 프로젝트 구조는 실행의 신뢰성을 만듭니다. 근거는 [커뮤니티형 협업](../resources/collaboration.md)에 있습니다.

## 8기에서 배운 것

5조 5징어가 8기 안에서 돌린 협력 게임은 참여가 낮았습니다. 관심사와 재능을 데이터로 잇는 것만으로는 협업이 생기지 않았고, 서로 편하게 이야기할 수 있는 관계가 먼저였습니다.
